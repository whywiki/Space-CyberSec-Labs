=== MISSION ORION INCIDENT ANALYSIS ===

1. unauthenticated command -> succeeds in insecure channel (task1); blocked by HMAC (task4+)
2. forged ROLE=admin command -> accepted by task2 receiver; blocked by token auth (task3+)
3. token captured from task3 channel -> attacker reuses token to authenticate as that user
4. SHUTDOWN with captured token -> succeeds against task3 receiver; blocked by HMAC (task4+)
5. forged HMAC without token -> blocked (INVALID AUTH / UNKNOWN USER)
6. replay of valid HMAC command -> succeeds against task4 receiver; blocked by replay protection (task5+)
7. confirm without valid request id -> blocked by safety gate (UNKNOWN REQUEST_ID)
8. tcpdump on TLS channel -> encrypted data, no readable fields

- easiest attack in insecure channel: manual nc injection with any crafted message
- role auth without authentication: attacker sets any role in their own message
- token over network: captured and reused for any future command
- HMAC better: never transmits the secret; receiver recomputes and compares
- HMAC does not prevent replay: same signed message is still valid on second send
- replay dangerous for commands: CMD=SHUTDOWN repeated can destabilize the satellite
- valid command still unsafe: timing, system state, or double-execution makes it dangerous
- TLS hides: all message fields from passive observer on the wire
- missing in lab vs real systems: PKI certificate management, hardware security modules, key rotation, multi-person authorization, formal command uplink protocols, out-of-band confirmation channels

=== FINAL REFLECTION ===

- insecure channel: anyone could send any command with any identity
- authorization blocked: operators from running admin commands
- authentication blocked: unknown users and role impersonation
- HMAC blocked: forgery and message tampering
- replay protection blocked: reuse of previously valid messages
- safety gate needed: to prevent immediate execution of dangerous commands even by legitimate admins
- HMAC no confidentiality: fields visible in plaintext; only the secret is hidden
- TLS no authorization: TLS encrypts transport but does not decide if a command is allowed
- real channel needs: mutual TLS, hardware tokens, time-limited tokens, formal uplink protocol
